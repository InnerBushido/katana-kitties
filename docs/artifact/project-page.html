Katana KittiesThe whole project on one page

A split-screen co-op browser game for up to four players: samurai kittens knocking over a chain of floating Japanese islands, riding storm dragons between them, and eventually fighting each other in a tournament ring in the sky. three.js and nothing else at runtime — no engine, no physics library, no asset store, no character meshes. Everything you can see is procedural or generated.

1 What it is, and who it is for

Two of its features exist to teach mathematics. They are not decoration.

Made for — and partly by — Richard's nieces, nine and younger. The cat-head title menu is a faithful redraw of one of their drawings, buttons and all. The six clan leaders came off a page of her character designs. The name was hers too.

There is a second reason it exists. One of them was being taught sine, cosine and the unit circle on graph paper, and this is that lesson made walkable: the Kotodama Orb draws its own working from the same two numbers that position it, and the Dojo of the Turning Circle is a unit circle you walk around until you are the point.

2 Run it, check it

Two check suites, and a browser rule that is not negotiable.

npm install
npm run dev        # http://localhost:5173 — then open it in FIREFOX
npm run build      # must stay clean; Vercel builds this on push to main
node tools/world-check.mjs    # 1889 checks: world, dragons, clans, sprites,
                              # tournament, consent, balance
node tools/pad-check.mjs      # 286 checks: controllers, keyboard sets,
                              # button prompts, the stuck-vJoy latch
npm run check                 # both of the above, in one line
npm run docs                  # this page's tables and PROJECT.md's, from the code
npm run artifact              # is this published page still current?
Play it in Firefox

Chrome cannot read Joy-Con sticks through vJoy — the buttons work and the axes report 0.00000 forever. It is a Chrome bug, unfixable from here, and it affects the Joy2Win/vJoy route only. Every other pad is fine in any browser.

Run world-check after touching the world, dragons, clans, the tournament or sprite directions. It catches what still looks fine on screen: a grove that generates zero canes, a clan buff that changes nothing, a sheet read in mirror image, a trade that quietly destroys an orb. Almost none of its assertions are about whether a number is set — they are about whether behaviour actually changed.

3 Test it — including on a phone

The local build reaches a phone over Wi-Fi in one command, and fails silently in three ways.

On a phone, over Wi-Fi

npm run dev -- --host

The -- is not decorative — it is what makes npm hand the flag to Vite instead of eating it. Vite then prints a second address:

  ➜  Local:   http://localhost:5173/
  ➜  Network: http://192.168.1.14:5173/  Wi-Fi

Type the Network one into the phone. That is the whole procedure. Same Wi-Fi as the laptop — the same SSID, not the guest network and not mobile data — and the address changes when the router hands out a new lease, so read it off the terminal each time. .claude/launch.json carries it as katana-kitties-lan.

Three things break it, and all three fail the same way

A timeout, with no error message anywhere. In the order they happen:

  • No --host. Vite binds 127.0.0.1 only, and still reports success. No Network: line in the terminal means this is it.
  • Windows Firewall blocking inbound Node. Verified rather than assumed on the development machine: four enabled inbound Allow rules for Node, scoped to the Public profile, which is what the house Wi-Fi is classified as. Elsewhere, the fix is one Allow rule — not turning the firewall off.
  • Router client isolation. Usually off by default, usually on for a guest network.
One caveat

--host also exposes /tuning.html, whose save endpoint POSTs a file into the source tree with no authentication. Fine on a home network with two children on it. Not fine in a café. Stop the server when the test is done.

What to check once it is on the phone

  • Landscape. Portrait is gated with a message rather than laid out badly.
  • The on-screen pad, which only exists on a touch device. Double-tap RUN or RIDE to lock it on.
  • The debug panel — five taps in the top-left corner within 600 ms, because a phone has no ` key. Every row in it is tappable. Deliberately the same gesture Android uses for developer options, and deliberately hard to stumble into mid-round.

Anywhere at all — the alpha channel

alpha is the testing channel. An ordinary long-lived branch with one job: it is the version other people are asked to play. Push to it and Vercel builds it within a minute at a stable address that never changes.

git checkout alpha && git merge main --ff-only   # alpha only ever FOLLOWS main
git push origin alpha

That link is the whole channel — there is no Discord, no TestFlight, no Steam beta. A tester opens the URL, or installs it to a phone's home screen and plays it fullscreen. main is what the girls play and is not for testing.

Alpha follows main; it does not lead it

Work lands on a typed branch, is merged into local main, and alpha fast-forwards to it. --ff-only is the whole rule, and it buys the property worth having: alpha can never carry a fix the real game does not have, so there is never a merge to bring back and never a question about which of the two is ahead in content. It is ahead only in release. Pushing alpha is not a way around the rule that origin/main waits until Richard has played it — it is the step before it.

Every other branch gets the same treatment, at katana-kitties-git-<branch>-dream-dojo.vercel.app, so a single risky change can be handed to somebody without going near alpha. No laptop has to be awake, it is real HTTPS, and it never takes the production alias. Preview URLs are public: SSO was deliberately turned off on 29 Aug 2026, because installing to a home screen needs the manifest and the icons fetchable and not merely the page.

Fullscreen on a phone is "add to home screen" — there is no fullscreen button anywhere in the source. The manifest does it. Each origin installs as its own app with its own localStorage, so an alpha install sits beside the real game and does not share the record board with it. Tell a tester that, or the first thing they report is having lost everything.

On a TV, or another PC

The non-Steam shortcut plus Steam Link works today — one remote player, nothing to write. Remote Play Together, the four-friends-over-the-internet one, is not available for non-Steam shortcuts. That is Valve's limit, not the game's.

4 Debug it, in play

Press ` to open the panel. It lists everything, and every row is tappable.

2Mr. Satan loses his temper — skips the ten-second fuse

4End the live round (feast)

6The endgame — ending, arena, orbs, purses
789Ryuuseki: take all seven stars & summon · seat both kittens · fire his beams
MZMaths overlay · map zoom
-=0Scene viewer: previous · next · play this scene
If somebody says it lags, press 1 before changing anything

The game is fill-bound: frame time is a straight line in the size of the drawing buffer, and everything else is rounding.

  • Read the last line first. Windows Firefox will happily render this on the integrated GPU with a discrete card idle in the machine — which is what "it lags" turned out to mean. The readout says ⚠ INTEGRATED GPU when it does.
  • Then read js against gap. A small js and a large gap is the GPU, not this codebase.
  • "Lag" is two different bugs. Slow is a long median. Stutter is a normal median with frames arriving unevenly — and the fps counter reads healthy the whole time it is happening. Believe a player who says the frame rate is fine and the game still chugs; the stutter figure is what sees it.
  • The maths overlay, the drifting petals and the tournament's critters have all been accused and all measured innocent. The numbers are in performance.md, so the next session does not spend itself re-accusing them.

5 Change the balance, without touching code

npm run dev, then open /tuning.html.

Every ability's timings and damage with a sentence each on what they do, a live timeline of the Cross Slash, and a save that writes src/tuning.json and hot-reloads the running game.

src/tuning.json holds overrides only. {} is the shipped balance; the literals in the code stay the defaults; tune() ignores anything that is not a finite number on a key the defaults already have. Neither the page nor the save endpoint exists in a build — the endpoint is a configureServer hook, which the production build never calls. A page that writes into the source tree is a fine thing on a laptop and an appalling one on the open internet.

The two Joy-Con halves get their own columns because they are separate controllers — held sideways, each with its own four-button cluster, and the two clusters are rotated differently in the driver. The left half's names are directions as she holds it, because a d-pad has no letters to appeal to.

  • □ Slash standing, dashing or airborne — three attacks, one button
  • ○ Action join a clan, buy from the dealer
  • △ Ride on and off a dragon or a panda
  • R2 Sprint and, on a dragon, boost
  • L1 Maths overlay · R1 Map

Every action in the second keyboard set has three keys, and that is not generosity — laptops have no numpad, and player 2's entire action set was once on it, so on a laptop the second kitten could walk and nothing else. P is mount, and nothing else on the keyboard may answer to P: it was once mount and the frame-cost debug key, so climbing onto a dragon flipped the performance readout on. pad-check asserts it of the whole debug set, because the failure was never about one line in one table.

On a phone, the on-screen pad produces exactly what a gamepad profile's read() produces, so the input manager seats it next to a Pro Controller and nothing downstream learns a new word. That property is also most of a future feature — see §10.

7 How every asset was made — and how to make another

Everything is generated. There is no asset store in this project.

WhatHowWhere
The 15 help clips The game, playing itself, recorded. A script drives the real game through a scripted performance, grabs one frame per tick straight off the WebGL back buffer, and hands the frames to the encoder. Nothing in the pipeline is capable of inventing a frame, which is why a clip can never lie about the game. tools/capture/
its README is the director's guide
GIF encoding Dependency-free GIF89a: median-cut palette, interframe differencing. dither: false is required, or the diff finds noise everywhere and bites on nothing. A self-test reads the encoder's own output back, because a codec bug presents as "the picture looks a bit off", never a crash. gif.mjs, gif-selftest.mjs
Looping two clips together Rewrites delay bytes only — no re-encode. It pads the last frame; it used to spread the shortfall across every frame, which stretched the whole clip a fifth slower and was caught by eye, not by the check. gif-sync.mjs
Sprite sheets Higgsfield image models. Two rules: a new player pose is four poses (all four kittens, never two), and everything goes through background removal — do not trust the runtime white-keyer. art.md
Voices ElevenLabs preset voices, reached through Higgsfield. Every character is pinned to one preset with an id — read the registry before generating any line, or the same cat comes back sounding like somebody else. voices.md
Sound & music Fully synthesised in code — a sound set, and a piece of music per island. The MP3s are the only audio files, and the game falls back to synthesised blips without them. core/audio.js
The 1:08 trailer Twelve five-second generated shots and an eight-second title card, a synthesised orchestra over the game's own music, a brush-drawn 十, and ffmpeg. 20 MB, and opt-in — the <video> carries no src until a player asks for it, and drops it again on close. trailer-vo.mjs, trailer-score.mjs, trailer-cut.sh
Steam shelf art & icons Crops and composites the title art into all six sizes. Nothing here is a new drawing — a prompt to an image model would put art on the box that is nowhere inside the game. steam-art.mjs, steam-capsules.sh
The rule under all of it

Measure, never reason, about anything drawn. Sizes, seat heights, mouth positions and facings are all read off the loaded atlas. Sprite sheets are measured, not assumed: column counts, cell sizes, baselines and facing come off the image, and a generated sheet's rows do not have to agree with each other. Reasoned numbers have been wrong roughly every time.

Know this before shipping anything publicly

Four of the sound files derive from somebody else's recording. The reference audio came off a social post, has always been kept out of the repo, and must stay that way — but the four files derived from it now ship with the game. A Steam release has to either license the source or delete those four files, and deleting them is real and cheap: the tool synthesises its own version without a reference, and the audio layer falls through to synthesised stand-ins after that. Three levels of degradation, on purpose, because the ninth non-negotiable says the game must work with the whole voice folder deleted.

9 The rules that must not break

Break any of these and the thing stops being the game it is. Each is enforced by world-check wherever a check can express it.

  1. The maths is the point, not a bolt-on. A prettier orb that lied about its own position would be worse than no orb.
  2. The art is the kids'. Don't redesign the cat-head menu or the six clan leaders.
  3. No combat outside the ring. One gate, asking one question. Enemies in the world have been rejected repeatedly and on purpose.
  4. Nothing regrows and nothing is lost. A prop knocked over stays knocked over, so the mischief counter is honest. A dragon can never be stranded; a pet can never be lost.
  5. Two players must keep the game they know. Everything four-player is additive, and the two-player answer has to come out bit-identical.
  6. A refusal must say so, and so must a confirmation. A button that silently does nothing reads as broken. Every dialog's buttons say what they do — "no, keep playing" against "yes, start over", never bare yes/no.
  7. Nothing irreversible happens on one press, and the default answer is no. A scene is skipped by Escape or a pad's Start and nothing else — never Space: four kids hold sticks and mash, and Space is the key an elbow finds. Confirm dialogs deliberately have no primary button, so the cursor opens on cancel.
  8. Sprite sheets are measured, not assumed. Never settle a facing by reasoning.
  9. Everything is procedural or generated. No engine, no physics library, no asset store, no character meshes, no new dependencies.
House style

Comments explain why, and name the thing that was tried and failed. This codebase's comments are its main defence against a fix being undone by somebody who could not see the reason. When you fix something, add the check that would have caught it — which is why world-check is 1888 assertions and why almost none of them are about whether a number is set.

And a change a new developer would need to know about gets a line in the God Doc — a new tool, document, account, cost, or a new way the project is built, tested or shipped. Not a refactor and not a bug fix: the test is whether anybody could find it out by reading the code. git log is the session log.

Git

Typed branches (feature/, bugfix/, mixed/), a commit-msg hook that stamps [branch] on non-main commits, a pre-commit hook that regenerates this page's tables, merged locally, and never pushed to origin/main until Richard has played it. Branches are kept until pushed, then git branch -d — never -D. alpha is the testing channel and only ever fast-forwards to main.

11 Where it is going

One question about playing across devices turned out to be four, with four different answers.

Build

A phone as a controller, screen stays on the host

The touch pad already produces exactly what a gamepad's read() produces, so this is one more device class rather than a new input path. WebRTC data channel, unreliable and unordered — 5–15 ms on the same Wi-Fi, under one frame. A QR code in the pause menu, a four-letter room code as backup. Roughly 1–2 sessions to a LAN prototype. It solves "four kids are in this room and there are two controllers", which is the only one of these four the game cannot already do at all.

Don't

Stream the picture to the phone as well

The game is fill-bound, so an extra full view plus a video encode lands squarely on the one axis it is known to be limited by. And it fights the design: the split screen is not a workaround for having one monitor — it is what makes four kids sit on one sofa.

Cheapest

Four friends over the internet

Steam Remote Play Together does exactly this with zero netcode — and is blocked by the shortcut, not by the game. So the cheapest route is publishing on Steam properly, which is a distribution decision, not an engineering one, and should be made on those terms rather than dodged by writing netcode.

A project

Real networked multiplayer

The obstacle is not the wire — it is that there is no seam between simulation and presentation. Host-authoritative with prediction for your own kitten is the realistic model; deterministic lockstep is the tempting wrong one, because one divergence and the two worlds silently disagree.

The backend that should come first anyway

The game currently saves nothing between sessions — only the record board, the controller calibration and the stick setting survive a reload, and the Help panel apologises for it in a warning box. Accounts and saved progress are a much easier project than netcode, independently useful, and the half players would actually notice. The leaderboard already has the shape; pointing it at a real table is a small change behind the same interface. Then national boards, and only then netcode — by which point there is an identity to hang a session on, which netcode needs anyway.

Nothing on the shortlist has an account yet: Cloudflare Durable Objects, PartyKit or a small always-on box for signalling; any hosted Postgres for progress; a Steamworks account for a store page. All deliberately deferred, so the expensive, hard-to-reverse decision is the last one rather than the first.

Smaller things on the list

  • The touch overlay's glyphs name buttons no phone has. Looked at and left alone on purpose — it reads acceptably as a mobile RUN button. Recorded so it is not re-opened as a bug.
  • Five help clips have no shot script, having been filmed before the capture rig existed. The other ten can be re-cut today.
  • A director skill. Searched on 29 Aug 2026 and there is none — nothing anywhere about in-engine cinematography, capture pacing or tutorial-clip authoring. So it would be a thing to write, and the material already exists in the capture rig's README: a caption needs longer on screen than the action under it; a pause is played at a lower frame rate rather than frozen, because a held frame reads as the picture having broken and was reported exactly that way; one idea per beat; pin the camera and pin the right one; hand the shot back to the game where the game already directs; trigger off state rather than off frame numbers. Plus the part nobody guesses — frame change is the cost, not frame count. Most of it is game-agnostic.

Keep this current. Anything a new developer would need and could not rediscover by reading the code gets a line: a tool, a document, an account, a cost, a future idea, or a new way the project is built, tested or shipped. A cheat sheet that has gone stale is worse than no cheat sheet, because it does not fail loudly; it quietly teaches somebody a thing that stopped being true. world-check enforces the register — every design note linked, every runnable tool named, every check total agreeing with the one the script actually prints.
